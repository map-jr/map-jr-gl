# MapLibre compatibility

This document compares the library with [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) version 6.

The API of MapLibre GL JS is in the entry `@map-jr/map-jr-gl/maplibre-compat`. The main entry, `@map-jr/map-jr-gl`, has another
API: see [The main API](api.md).

It has six parts:

1. [What this library adds](#what-this-library-adds)
2. [What is different](#what-is-different)
3. [What is not available](#what-is-not-available)
4. [Map methods](#map-methods)
5. [Source methods](#source-methods)
6. [Types](#types)

The [status table](../README.md#status) gives the current test results.

## What this library adds

| Feature | Description |
|---|---|
| Worker rendering | The renderer can run in a worker. The option is `renderer: 'auto'`, `'worker'` or `'main'`. |
| Server rendering | `renderToSVG` and `renderToImage` draw a map without a browser. See [Server rendering](server-rendering.md). |
| Many markers | A symbol layer draws icons that are always shown from a buffer on the GPU: the cost of a frame does not grow with their number. See [Which icons are fast](markers.md#which-icons-are-fast). |
| SVG images | `addImage` accepts an SVG string. The image is sharp on each screen. Its size in CSS pixels is the size of its `viewBox`, or else of its `width` and `height` attributes, or 24 by 24. |
| Many icons | A symbol layer draws an icon that is always shown (no text, `icon-allow-overlap`) from a buffer on the GPU. Such an icon is not hidden by ground in front of it with 3D terrain, does not fade in, and is drawn below the labels of the symbol layers next to its layer (those with no other visible layer between them) unless its layer is above each layer with labels. See [Markers](markers.md). |
| SVG templates | An SVG string with slots (`{{name}}`) is a template. Each feature gives the slots their values, from its properties or from `params` of the `image` expression: `['image', 'pin', {params: {color: ['get', 'color']}}]`. MapLibre GL JS does not have `params`. See [An image that is a template](api.md#an-image-that-is-a-template). |
| The global state property `color-scheme` | A map of `@map-jr/map-jr-gl` sets the global state property `color-scheme` of the style to `'light'` or `'dark'`, the resolved `colorScheme` of the description. The compat entry does not set it. The name is not reserved in the MapLibre style specification: MapLibre GL JS shows such a style with the default in `state` of the style, so give one (`state: {'color-scheme': {default: 'light'}}`). See [Dark mode](api.md#dark-mode). |
| Fonts | Text uses the glyph files of the style (`glyphs`), as in MapLibre GL JS. A style without `glyphs` needs no glyph files: text then uses the fonts of the browser. The option `glyphs` of earlier versions is removed; to use the fonts of the browser, remove `glyphs` from the style. The style can also give font files in `font-faces`. |
| `queryFeatures`, `querySource` | Find features, with the meaning that they have in `@map-jr/map-jr-gl`. `querySource(sourceId, at, options)` reads the tile data of one source, and you do not need a style layer. `queryFeatures(at, options)` gives what the style layers draw. See [Queries](api.md#queries). |
| `queryElevation` | Gives the elevation at a position from a `raster-dem` source. |
| Contour source | `type: 'contour'` makes contour lines from an elevation source. See [Terrain and elevation](terrain-and-elevation.md). |
| PMTiles | A source URL that starts with `pmtiles://` reads a PMTiles archive. You do not need a plugin. |
| Changes for the server in the style | `metadata["map-jr:ssr"]` on a layer changes that layer only on the server. |
| Images in the style | `metadata["map-jr:images"]` of a style gives images by name. The main entry (`@map-jr/map-jr-gl`), the compat entry (`@map-jr/map-jr-gl/maplibre-compat`) and the server renderer draw them; MapLibre GL JS ignores the key. An image of the style wins over the sprite image of the same name. In the compat entry, an image that the page adds with `addImage` wins over an image of the style with the same name, and `setMissingStyleImageResolver` gets only the names that the style does not have. See [Images in the style](api.md#images-in-the-style). |
| Icons generated on demand | `setMissingStyleImageResolver` supplies an image for a name that the sprite does not contain. |
| `toBlob(type, quality)` | Gives the map as an image: it waits until the map is idle, draws one frame and resolves to a `Blob` of the canvas, with both renderers. Use it instead of `preserveDrawingBuffer`, which has no effect (see "Reading the canvas" in [What is different](#what-is-different)). |
| Frame data | The `stats` event gives the frames per second and the work for each frame. |
| `supported()` | A function of the module. It returns `false` in a browser without WebGL2. MapLibre GL JS has had no such function since version 2. A map that cannot start fires one `error` and shows a message in the container (the class is `map-jr-unavailable`). See [A browser without WebGL2](api.md#a-browser-without-webgl2). |
| Controls without a CSS file | The library adds the styles for its controls to the root node of the container, so a map inside a shadow root has styled controls. You change the colours with `--map-control-*` custom properties. The rules for the buttons and links of the controls have the specificity of one class, as in MapLibre GL JS, so a page rule for `button`, `a` or `svg` does not change them and a page rule for a button needs two classes. The other rules (the groups, the attribution, the scale, the icons) have no specificity, so a page rule with one class, such as `.maplibregl-ctrl-group {background: #010101}`, wins. The map option `nonce` sets the nonce of a strict `style-src` on the `<style>` element that a browser without constructed style sheets gets. See [Content Security Policy](loading.md#content-security-policy). |
| The look of the controls | The controls, the popup, the scale and the attribution of the compat entry keep the look of MapLibre GL JS. The round, translucent look, the compass with a dial and the control `colorScheme()` belong to the main API (`@map-jr/map-jr-gl`) only. The popup of both entries fades and grows from its tip when it opens and closes, where the popup of MapLibre GL JS has no animation; `animate: false` turns it off. |

## What is different

| Subject | MapLibre GL JS | This library |
|---|---|---|
| The attribution after a change of the global state | A source appears in the attribution when a `visibility` expression of the global state shows its layers. When the state hides them again, the source stays in the attribution until the next change of a source (measured with 6.17). | The attribution names a source while one of its layers is visible, and drops it when the state hides its layers again. |
| Text | Reads glyph files from the `glyphs` URL. | The same: glyphs and their widths come from the glyph files. Two cases use the fonts of the browser, or the web fonts of `fonts` (the option of the compat entry, or the field of the description of the main API): a character, font stack or range that the files do not have (most ideographs, emoji), and text that the browser must shape (Arabic, Hebrew, Indic scripts). This is like `localIdeographFontFamily` of MapLibre GL JS. A label waits for its glyph file, as in MapLibre GL JS. The map requests the file of the first 256 characters (`0-255`) of each font stack of the symbol layers in view when it starts, at the same time as the first tiles; MapLibre GL JS requests a glyph file only once a tile needs it. In both, text drawn with the fonts of the browser uses each name of the `text-font` list in order, with the weight and the style of the first name. Where this library differs: it takes the weight and style words out of each name (`Open Sans Bold` is the family `Open Sans`, where MapLibre GL JS asks for a family named `Open Sans Bold`), it quotes every name except a CSS generic family keyword (MapLibre GL JS leaves nearly every name unquoted, and a name that is not a valid CSS identifier, such as one that starts with a digit, makes the font string invalid), and it tries `fontFamily` after the list, where MapLibre GL JS tries `sans-serif`. MapLibre GL JS uses `localIdeographFontFamily` alone for ideographs of the default font stack; this library has no such option and draws them with the same family list. |
| Text on lines | Each character follows the line. The style sets the largest angle. | Each character follows the line. A label does not show where the line turns more than about 35 degrees between characters. |
| `fill-sort-key` and `line-sort-key` with a pattern for each feature | The sort key orders all features of the layer. | The sort key orders the features that have the same image. The features of each image are drawn together (#1445). |
| Order of symbol layers | A symbol layer draws at its position in the layer list. | The same without 3D terrain: a fill, line or other layer between two symbol layers draws over the labels of the symbol layers before it and below the labels of those after it. Symbol layers that follow each other with no other visible layer between them draw their labels together. With 3D terrain, the labels of all symbol layers draw together, at the position of the last symbol layer that has labels, and the layers on the ground draw below all labels. |
| A heatmap below an opaque layer | A heatmap is drawn over an opaque fill or background layer that is above it in the style. | The layers draw in the order of the style, so the opaque layer covers the heatmap. This is a decision and will stay. |
| Label placement | Changes gradually, tile by tile. | The library decides about four times each second. Labels fade between decisions. |
| Feature queries | `queryRenderedFeatures` and `querySourceFeatures` return their result synchronously. | The two methods have the same arguments and return the same features, but the complete result is a promise. Add `await`. The tile data is in a worker. Without `await`, the value of each of the two methods is an array. For `queryRenderedFeatures` the array has the answer of the engine to the same question before (the same view, place and layers). Two rules make that answer present for usual MapLibre code. The map asks the engine about the place of a `mousedown` or `touchstart` and where the pointer rests for 50 ms. A `click`, `dblclick` or `contextmenu` listener that queries `e.point` therefore gets the features at once. When the answer is not there yet, the event waits for it for at most 300 ms, and after that the array has GeoJSON features only. A `mousemove` listener that reads the array gets the same `mousemove` a second time when the answer arrives and the pointer has not moved since, so hover through react-map-gl (`interactiveLayerIds`, `onMouseEnter`, `cursor`) works; the listener sees the first event with an empty array. When an array did not have the complete result, the map fires `idle` again, so code that queries on `idle` gets the features on its next call. For `querySourceFeatures` the array has the last answer of the engine for the same source and options (`sourceLayer`, `filter`), from any view, once the promise of an earlier call has settled. A change of the style keeps that answer, and new data of the source (`setData`, `refreshTiles`, `removeSource`) drops it. When that answer has more features than the array that the earlier call gave, the map fires `sourcedata` and `data` again for the last tile of the source that loaded, one time for that question, so code that queries when a tile loads, as Maputnik does, gets the features on its next call. Without an answer before, the array has the features of GeoJSON sources only. The features of a GeoJSON source whose data the page has are always read from that data, so they are current after `setData`: this is sufficient for plugins such as mapbox-gl-draw and for code that makes HTML markers from clusters. (For a GeoJSON source with its data at a URL, the first call gives an empty array; the source then fires its data events again, and the next call has the features.) A feature that several tiles hold is in the result one time when it has an id or comes from a GeoJSON source. MapLibre GL JS returns such a feature once for each tile whose area it touches: a GeoJSON polygon over the corner of four tiles comes four times from `queryRenderedFeatures` of MapLibre GL JS and one time here, and `querySourceFeatures` of MapLibre GL JS gives each feature once for each loaded tile that holds it. Two GeoJSON features with the same id are two results, as in MapLibre GL JS. `querySource` is also available: it reads data that the style does not draw. The promise is a decision and will stay: the tile data is in a worker, so the library has no synchronous result. |
| Queries on labels | A label is found on the collision boxes of its text and of its icon. | The same for text at a point and for icons. Text that follows a line is found within 10 pixels of the point of its label, and so is a label whose text is not shown at the moment. |
| Feature state | The GPU applies the state. An `id` can be text. | `setFeatureState` and the `feature-state` expression work. A change builds the tiles of the source again in the background when a layer of that source reads feature state, so it shows after a short time. On a GeoJSON source, the `id` of a feature is its `id`, or the value of the property that `promoteId` names. Each can be a number or a string. A string `id` of a GeoJSON feature that is decimal digits and a safe integer becomes the number, as in MapLibre GL JS: `'12'` and `'012'` give `12`. Any other string `id` stays the string in `queryRenderedFeatures` and `querySourceFeatures`, and `setFeatureState` takes it. MapLibre GL JS 6.17.0 reads a string `id` with `parseInt` and gives a number for every one, so there a string needs `promoteId`: measured, it gave `0` for `'square-a'`, `1` for `'1.5'`, `7` for `' 7'`, `18446744073709552000` for `'-3'` and `9007199254740992` for `'9007199254740993'`, where this library keeps the string. `promoteId` can also be an object, as in MapLibre GL JS: a GeoJSON source reads the property under the key `_geojsonTileLayer`. On a vector source, the `id` is the numeric `id` of the feature in the tile, or the value of the property that `promoteId` names, as in MapLibre GL JS: `promoteId` is a property name, or an object with a property name for each source layer. A string value stays the string, a boolean becomes `0` or `1`, and a feature without the property has no id. Without `promoteId`, a `setFeatureState` call with an `id` that is text (not digits) on a vector source changes nothing and writes one warning for the map. `setFeatureState` and `getFeatureState` with a feature that has no `id` change nothing and write one warning; MapLibre GL JS fires `error`. |
| Style changes | Applied step by step. | A paint value that is the same for all of a layer is applied immediately. Other changes build the tiles of that source again. The old tiles stay on the screen until the new tiles are ready. |
| 3D terrain | Draws terrain at each tilt. | Draws a flat map when you look vertically down. See [Terrain and elevation](terrain-and-elevation.md). |
| Camera | Tilt to 85 degrees. Roll. Field of view. | Tilt to 60 degrees. No roll. A fixed field of view. Padding is available. |
| Miter joins longer than about 2 | A miter join whose length is more than 127/63 (about 2.02) times the line width breaks into a notch, because the extrusion of the vertex overflows its byte (the render test `line-miter-limit/global-state` shows it). | Draws the full miter up to `line-miter-limit`. |
| The lowest zoom | `minZoom` is -2 by default. The world is never less tall than the map. | The same. |
| The `cooperativeGestures` option | The wheel zooms only with Ctrl (⌘ on a Mac), one finger scrolls the page, two fingers move the map, and a hint shows over the map. `map.cooperativeGestures` has `enable()`, `disable()`, `isEnabled()` and `isBypassed()`. | The same behaviour and the same hint. The option `locale` changes the text of the hint, with the keys of MapLibre GL JS (`CooperativeGesturesHandler.WindowsHelpText`, `MacHelpText` and `MobileHelpText`). The event `cooperativegestureprevented` fires with `gestureType` (`'wheel_zoom'` or `'touch_pan'`) and `originalEvent`. `isBypassed()` is not there. The code of the hint loads on demand when the option is on. Until it has loaded, the gestures are blocked and the hint does not show. The hint has its look in its `style` attribute, and the class `maplibregl-cooperative-gesture-screen` for stylesheets. |
| The `hash` option | The camera in the fragment of the URL. | The same, with the same format. |
| Tile URLs | `{z}`, `{x}`, `{y}`, `{bbox-epsg-3857}`, `{quadkey}`, `{ratio}`, `{prefix}`; the `scheme` `tms`. | The same. `{bbox-epsg-3857}` is for WMS servers. `{ratio}` is `@2x` when the pixel ratio of the map is above 1, for every kind of source, as in MapLibre GL JS. |
| The `bounds` of a source | A tile outside the bounds is not requested. | The same, for bounds in the style and in the TileJSON. Not for the bounds in the header of a PMTiles file. |
| An image tile that the server does not have (404) | The nearest tile above it is drawn in its place. | The same, for raster and elevation tiles. |
| GeoJSON sources | `setData`, `getData`, `updateData`, the cluster methods. | The same. `updateData` makes the new data from the old data and the changes, and then replaces the data of the source in one step. The `buffer` option sets how far past its edges a tile keeps the features, in pixels of a tile 512 pixels wide, as in MapLibre GL JS (at most 512). Without `buffer`, a tile keeps 128 pixels, as in MapLibre GL JS (the main entry `@map-jr/map-jr-gl` keeps 16). |
| `Marker` and `Popup` | Rotation, pitch alignment, offsets, class names. | The same methods. `pitchAlignment` is kept but has no effect: a marker is always upright on the screen. `Popup` has the options `focusAfterOpen`, `closeOnMove`, `trackPointer` and `subpixelPositioning` with the defaults of MapLibre GL JS, and the methods `trackPointer()` and `setSubpixelPositioning()`. A popup that follows the pointer does not move with a touch. With the worker renderer, a marker or popup moves in the same frame as the map during a drag, but it can trail an `easeTo`, `flyTo`, a fling or a pinch by about one frame, because the page learns the camera from the worker after the frame. A symbol layer never trails. See [How closely an element of the page follows the map](markers.md#how-closely-an-element-of-the-page-follows-the-map). |
| `Point` | Re-exports `Point` of `@mapbox/point-geometry`, with about 30 methods. | Exports a smaller `Point` with `convert`, `clone`, `add`, `sub`, `mult`, `div`, `round`, `mag`, `dist` and `equals`. The other methods (for example `rotate`, `unit`, `angle`, `matMult`) do not exist. |
| Private members that wrappers read | `Marker._map`, `Marker._lngLat`, `Map._controls` are internal fields. | `Marker._map`, `Marker._lngLat` and `Map._controls` exist as read-only getters with the same values. `map.style` exists before the style has loaded (with `_loaded` `false`), has `updateImage` (svelte-maplibre-gl reads it), and has `_loaded`, and `tileManagers` (also named `sourceCaches`, as in MapLibre GL JS 5) with one entry for each source; the entry has only `_source` with `id`, `type` and `vectorLayerIds`, the ids of `vector_layers` of the TileJSON of a vector source (Maputnik reads them). `map.style.projection.subdivisionGranularity` has `fill`, `line`, `tile` and `stencil`, each with `getGranularityForZoomLevel(z)`, and `circle`, with the values of MapLibre GL JS 6.17 for the projection of the style (the example page "Add a custom layer with tiles to a globe" reads it); the map draws a custom layer only while the projection is Mercator. `map.transform` and `getTransformForUpdate()` (also `_getTransformForUpdate()`, and `_stop(true)`, which is `stop()`) give a copy of the camera with `center`, `zoom`, `bearing`, `pitch`, `roll` (always 0), `elevation` and `isPaddingEqual`, which svelte-maplibre-gl reads. Other private members do not exist. |
| TypeScript types | Exports types and classes such as `MapMouseEvent`, `StyleSpecification`, `GeoJSONSource`. | Exports types with the same names (`src/compat-types.ts`). The event and source names are types only: you cannot use them with `new` or `instanceof`. The style types do not check each property: `LayerSpecification` accepts any string as `type` and any names in `paint` and `layout`. `map.on`, `map.once` and `map.off` give the listener the event type that belongs to the name of the event (`MapEventType`, `MapLayerEventType`), and an event name that is not in those lists gets an event of the type `any`. The geometry of a queried feature is the library's own `Geometry` type, which has no `GeometryCollection`. The compat types accept values that are typed with `maplibre-gl`, such as a `StyleSpecification`, a layer, a source or a filter. The reverse direction does not work: a value typed with the compat entry is not always assignable to a type of `maplibre-gl`, and a compat `MapLayerMouseEvent` is not assignable to the one of react-map-gl. A project that uses react-map-gl therefore keeps `maplibre-gl` installed and imports its types from `maplibre-gl`. |
| `isSourceLoaded` | Gives a result for one source. An id that the style does not have fires `error`, and the result is `undefined`. | The same. The message of the error is `There is no source with ID "<id>"`, and MapLibre GL JS 6.17 writes `There is no tile manager with ID '<id>'`. |
| `addImage` | Accepts images and pixel data. | Accepts the same, and also an SVG string or a URL. It returns a promise. |
| `easeTo`, `flyTo` | Accept an `easing` function and an `offset`. | Accept both, as MapLibre GL JS does. `offset` ([x, y] or {x, y}, in CSS pixels) puts `center` at that distance from the centre of the view at the end, also with `bearing` and `pitch`. The library samples the `easing` function at 65 points when the call is made and interpolates linearly between them, so a curve with a change that is narrower than 1/64 of the duration is smoothed. `flyTo` zooms out and back in along the curve of MapLibre GL JS 6.17 (van Wijk and Nuij), with the options `curve`, `speed`, `screenSpeed`, `minZoom` and `maxDuration`; without `duration`, the duration follows from the distance. When the system asks for reduced motion and `essential` is not `true`, `flyTo` jumps, as in MapLibre GL JS. `fitBounds` and `fitScreenCoordinates` fly in the same way, or ease as `easeTo` does when the options set `linear`, as in MapLibre GL JS. |
| Events | Event classes. | Simple objects with `type`, `target`, `point` and `lngLat`. `point` (and each of `points` of touch events) is a `Point`, as is the result of `project()`. |
| Data events of tiles | `data` and `sourcedata` fire with `dataType: 'source'` and `e.tile` for each tile that loads. `e.tile` is a `Tile` object. | The same events fire for each tile that loads, after a listener for `data` or `sourcedata` has been added (tiles that loaded before do not fire). `e.tile` is a plain object with `tileID` (`canonical` with `z`, `x`, `y` and `key`, `overscaledZ`, `wrap` that is always `0`, `key`) and `state` that is `'loaded'`; it has no other member of the `Tile` class. `e.coord` is the same `tileID`, and `e.source` is the result of `getSource(sourceId)`. |
| Events for one layer | `map.on('click', layerId, fn)` calls the listener synchronously. | The same call works, also with an array of layer ids (`map.on('mouseenter', ['a', 'b'], fn)`). A second argument that is neither a layer id, an array of layer ids nor a function makes `on` throw a `[map-jr-gl]` error. The event fires shortly after the pointer event, because the library reads the tile data. |
| Interaction handlers | `map.dragPan`, `map.scrollZoom`, `map.boxZoom` and others, each with `enable()` and `disable()`. | The same objects are available: `dragPan`, `scrollZoom`, `doubleClickZoom`, `dragRotate`, `touchZoomRotate`, `touchPitch`, `keyboard`, `boxZoom`. `isActive()` is `true` during the gesture for `dragPan` (from the press of the mouse button, or from the first movement of one finger), `dragRotate` (from the first movement of a rotate drag), `touchZoomRotate` (a pinch), `touchPitch` (a tilt with two fingers) and `boxZoom` (from the press of the mouse button with Shift held). It is `false` again when a pointer of the gesture lifts, and during the movement that follows a drag. `isActive()` of `scrollZoom`, `doubleClickZoom`, `keyboard` and `cooperativeGestures` always returns `false`, and `dragPan.isActive()` stays `false` during a pinch. Box zoom works as in MapLibre GL JS: a drag with Shift held and the left mouse button draws a box, zooms to it, and fires `boxzoomstart`, `boxzoomend` (with `boxZoomBounds`) or `boxzoomcancel`. Box zoom does not work with touch input. With `interactive: false`, every handler is off, and the map still fires `click`, `mousemove` and the events of layers, as in MapLibre. The `interactive` option of `@map-jr/map-jr-gl` behaves the same. |
| Rotate drag (the right mouse button, or Ctrl with the left one) | More than 100 pixels above or below the centre of the map, the map turns by the angle that the pointer makes around that centre. Nearer to the centre, the map turns by 0.8 degrees for each pixel sideways: a drag to the right increases the bearing below the centre and decreases it above the centre. The map pitches by 0.5 degrees for each pixel up. After the drag, the map turns on with inertia. A drag with Ctrl and the right button rolls the map. The compass of `NavigationControl` turns the map by the angle around the centre of the button. | In both entries, the drag turns and pitches the map by the same angles (measured against MapLibre GL JS 6.17.0 at five heights of the map). After a drag that is released while it moves, the map turns and pitches on with the inertia of MapLibre GL JS (the speed of the last 60 ms, at most 360 degrees per second for the bearing and 90 for the pitch). A drag with Ctrl and the right button turns and pitches the map as a drag with the right button does, because the map has no roll. The options `rotateSpeed`, `pitchSpeed` and `aroundCenter`, and an object as `dragRotate` (`around`, `movement`), have no effect. The compass of both entries turns the map by 0.4 degrees for each pixel sideways, and a drag to the right decreases the bearing: an angle around the centre of the button makes the map jump when the pointer passes near that centre. |
| Pointer events | `mousedown`, `mouseup`, `touchstart` and others, with `preventDefault()`. | The same events. A listener that calls `preventDefault()` on `mousedown`, `touchstart`, `wheel` or `dblclick` stops the map from acting on that gesture. |
| `setWorkerUrl` | Sets the URL of the worker file of MapLibre GL JS. | Sets `workerUrl` of `configure`. The URL must point to `map-jr-gl-worker.js`. A URL whose file name contains `maplibre-gl` and `worker` (such as `maplibre-gl-worker.mjs`) is ignored with one warning, and `getWorkerUrl()` then still returns `''`. Remove the call: the library finds its worker file itself. |
| Requests | The `transformRequest` option and `addProtocol`. | The same. The functions run on the page; the workers ask the page for each request that they apply to. A protocol named `pmtiles` is not used: the library reads `pmtiles://` URLs itself, and `addProtocol('pmtiles', …)` warns once in every build. Remove that call. A tile of a `raster` or `raster-dem` source has the request type `image`, and the protocol can answer with an `ImageBitmap`, an `HTMLImageElement` or the bytes of an image file. An image of `addImage` and the image of a sprite have the type `arrayBuffer` (MapLibre GL JS gives `image`), and only bytes are read as their answer. |
| `Marker`, `Popup` | Full API. | The usual parts of the API: position, popup, drag, anchor, offset. `Map.remove()` removes the popups and the markers of the map from the page at once, and each open popup fires `close`, as in MapLibre GL JS. `offset` and `setOffset` take `[x, y]`, `{x, y}` or a `Point`. `getOffset()` returns a `Point`, as in MapLibre GL JS. |
| The Escape key in a `Popup` | Does not close the popup. An application adds a listener for the key. | Closes a popup that has a close button while the keyboard focus is inside the popup, as a click on the button does: the popup fires `close`, and the focus returns to the marker of the popup, or to the canvas of the map. The popup calls `preventDefault()` and `stopPropagation()` on that `keydown` event. A popup with `closeButton: false` does not react, and neither does a popup whose content called `preventDefault()` on the event. |
| `addImage` with an image that draws with WebGL | Accepts an image whose `data` has `renderWithWebGL` (`StyleImageWebGLData`). | Not supported. The promise rejects with an error that names the image, and the map keeps working. |
| `updateImage` | Replaces the pixels of an image in place and keeps its options. New pixels of another size fire an `error` event, and the image stays as it was. | Replaces the pixels in place and keeps the options, as MapLibre GL JS does, and the icons keep their places. ## What is not available

Sources:

- MapLibre Tiles (MLT). A `vector` source with `encoding: 'mlt'` is not drawn, and the map reports one error for it, as for a source that has no `tiles` and no `url`. The other sources are drawn.

Layers:

- Custom layers with the worker renderer (see "Custom layers" in [What is different](#what-is-different))

Properties:

- `line-gradient` together with `line-dasharray`
- `line-offset` and `line-blur` that are different for each feature
- Circle stroke and blur that are different for each feature
- `line-gap-width` that is different for each feature. The line is drawn without a gap, and nothing warns.
- `line-round-limit` in the server renderer. Its SVG does not apply the property, because SVG has no equivalent, so a round join rounds every corner.
- `heatmap-radius` that is different for each feature. The layer uses the default radius of 30 pixels, and nothing warns.
- `text-writing-mode`
- `text-pitch-alignment` and `icon-pitch-alignment` with `map` at a point are approximations. The symbol lies on the ground with the slant of the ground at its anchor, so a large symbol near the horizon is not as wide at its far edge as MapLibre GL JS draws it. Images inside text lie on the ground with their text (#1064). An icon with `icon-text-fit` faces the screen. Since #1073, the SVG output of the server renderer (`renderToSVG`) draws point text, icons and images inside text with `map` on the ground in the same way, and it draws images inside text (#1079). In the SVG, text along a line keeps its characters upright to the screen, and an icon with `icon-text-fit` faces the screen.
- On a rotated icon, the four sides of `icon-padding` are added to the screen-aligned box of the rotated icon, and not before the rotation as in MapLibre GL JS. With no rotation, the box is the same as in MapLibre GL JS.
- `symbol-z-order` sorts the symbols within each tile by the y of their anchor in the tile, turned with the map, as MapLibre GL JS does. The order is found at each placement (about four times a second while the map moves), so it can lag behind a map that rotates. Icons without text that always show (`icon-allow-overlap` with no `text-field`, at a point) keep their order while the map turns, and are sorted again in the first frame after the turn.
- `symbol-avoid-edges`. The property is not read, and nothing warns.
- `symbol-height-offset`. The property is not read, and nothing warns.
- `fill-extrusion-rounded-corner-distance`. The property is not read, and nothing warns: the corners of an extrusion are sharp.
- `raster-fade-duration`. A raster tile shows at once when it has loaded. A value other than 0 has no effect and writes one warning. (`raster-resampling`, `resampling` and `raster-layer-blend` are read as in MapLibre GL JS; the SVG output of the server renderer gives `nearest` to the browser as `image-rendering: pixelated`.)
- Paint transitions of symbol layers, of fill-extrusion layers and of `fill-outline-color`. The tiles hold these values, so a new value shows when the tiles are built again, with no transition, and nothing warns. Paint transitions of the other layer types are available: see [Paint transitions](api.md#paint-transitions).
- An icon together with text that follows a curved line. The text is drawn without the icon.
- `vertical-align` in `format` text. Sizes, fonts, colours and images in `format` text are available. The SVG output of the server draws each line in one size.

Expressions:

- `within` and `distance`. Each writes one warning (`[map-jr-gl] Unsupported expression "within"`) and gives `null`, so a property takes its default value, and a filter that is `["within", ...]` alone lets no feature through.

Layers that the server renderer does not draw:

- The layer types `heatmap`, `hillshade` and `color-relief`

Other:

- Projections other than `mercator`, `globe` and `vertical-perspective` (`addProjection`)
- The map option `crossSourceCollisions: false` of `@map-jr/map-jr-gl/maplibre-compat`. The option is not read, and nothing warns: labels of different sources always collide with each other, as with the default (`true`) of MapLibre GL JS.
- The right-to-left text plugin. The browser draws right-to-left text correctly without it, so `setRTLTextPlugin` is accepted and does nothing. This is a decision and will stay.
- The debug drawing of MapLibre GL JS: collision boxes, padding lines, tile borders and the overdraw view (`showCollisionBoxes`, `showPadding`, `showTileBoundaries`, `showOverdrawInspector`). This is a decision and will stay.

## Map methods

The camera methods of the entry `@map-jr/map-jr-gl/maplibre-compat` (`jumpTo`, `easeTo`, `flyTo`, `fitBounds`, `fitScreenCoordinates`, `panTo`, `panBy`, `zoomTo`, `zoomIn`, `zoomOut`, `rotateTo`, `resetNorth`, `resetNorthPitch`, `snapToNorth`, `setCenter`, `setZoom`, `setBearing`, `setPitch` and `setPadding`) take `eventData` as the last argument, as in MapLibre GL JS. Its fields are on the `move`, `zoom`, `rotate` and `pitch` events of that move, from `movestart` to `moveend`. A later camera call replaces it.

The option `zoomSnap` and `setZoomSnap` work as in MapLibre GL JS: with a value above 0, the zoom of `jumpTo`, `easeTo`, `flyTo`, `zoomIn`, `zoomOut`, the double-click, the keyboard and the navigation buttons goes to the nearest multiple of the value, and `cameraForBounds` and `fitBounds` go to the multiple below. The scroll wheel and the pinch do not snap here, while MapLibre GL JS snaps the scroll wheel.

`setEventedParent(parent, data)` passes each event of the map to `parent.fire` while `parent.listens(type)` is true, as one object with the fields of the event and of `data` (an object, or a function that returns one). The parent gets a `click` after the listeners of the map.

The methods `calculateCameraOptionsFromTo`, `calculateCameraOptionsFromCameraLngLatAltRotation` and `calculateAnchoredCameraOptions` compute camera options without changing the map, with the math of MapLibre GL JS for the Mercator projection. On a globe they also use the Mercator math: MapLibre GL JS follows the sphere there, so the results differ. `calculateCameraOptionsFromCameraLngLatAltRotation` returns the `roll` that it is given, and `setRoll` has no effect.

`setTransformConstrain(fn)` and the option `transformConstrain` replace the constraint of the camera, as in MapLibre GL JS: `fn(lngLat, zoom)` returns `{center, zoom}`, and `null` restores the default, which keeps the view inside the world and inside `maxBounds`. `minZoom` and `maxZoom` still apply. The function runs in the engine on each change of the camera, so it needs `renderer: 'main'`. With the option and no `renderer`, the map draws on the main thread. On a map that draws in a worker, `setTransformConstrain(fn)` has no effect and warns once.

`coveringTiles({tileSize, minzoom, maxzoom, roundZoom})` returns the tiles that the library loads for the view, synchronously, as objects with the fields `canonical` (`z`, `x`, `y`, `key`), `wrap`, `overscaledZ` and `key`. The objects are plain and do not have the methods of MapLibre's `OverscaledTileID`, and `key` is a string, not MapLibre's number. `overscaledZ` equals `canonical.z`, as in MapLibre GL JS for this method. The default of `maxzoom` is 30. A pitched view and a globe use the tile cover of this library, which can choose other tiles at the edges than MapLibre GL JS.

`setSourceTileLodParams(maxZoomLevelsOnScreen, tileCountMaxMinRatio, sourceId?)` changes the level of detail of a pitched view for one source, or for all sources of the style when `sourceId` is left out, with the rule of MapLibre GL JS: each value below 1 counts as 1, and an unknown `sourceId` throws an error. The parameters apply above a pitch of 60° and with 3D terrain, as in MapLibre GL JS, and then near tiles can go deeper than the zoom of the centre, up to the `maxzoom` of the source. Without them, a pitched view without terrain uses the tile cover of this library. The parameters stay with the source ID when the style changes, while MapLibre GL JS drops them with a new source object. `coveringTiles` does not use them.

## Types

The entry `@map-jr/map-jr-gl/maplibre-compat` exports types under the names of MapLibre GL JS 6.17 (`src/compat-types.ts`). Each type describes what this library accepts, so a type can have fewer members than the type of MapLibre GL JS. The row "TypeScript types" in [What is different](#what-is-different) describes the event, source and style types.

These types differ from MapLibre GL JS:

| Type | In this library |
|---|---|
| `NavigationControlOptions` | It has no `visualizeRoll`. |
| `GeolocateControlOptions` | It has `zoom` and no `fitBoundsOptions`. `showAccuracyCircle` has no effect. |
| `FullscreenControlOptions` | `container` has no effect. |
| `LogoControlOptions` | `compact` has no effect, and the constructor of `LogoControl` takes no argument. |
| `Offset` | It is a number, `[x, y]`, or `[x, y]` for each anchor. It does not accept a `Point`. |
| `Listener` | Its type parameter is the type of the event, and the default is `MapLibreEvent`. |
| `Subscription` | No method returns it: `map.on` returns the map. Remove a listener with `map.off(type, listener)`. |
| `FullscreenControlEventType`, `GeolocateControlEventType`, `PopupEventType`, `EventTypeMap` | An event is a plain object with `type` and `target`, and not an instance of the class `Event`. The event of `geolocate` has `coords` and `timestamp`, and the event of `error` has `code` and `message`. |
| `DragPanOptions`, `DragRotateOptions`, `AroundCenterOptions` | They have no effect: `enable()` of a handler does not read its argument, and the options `dragPan` and `dragRotate` of `new Map()` are booleans. |
