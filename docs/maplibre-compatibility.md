# MapLibre compatibility

This document compares the library with [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) version 6.

The API of MapLibre GL JS is in the entry `@map-jr/map-jr-gl/maplibre-compat`. The main entry, `@map-jr/map-jr-gl`, has another
API: see [The main API](api.md).

It has four parts:

1. [What this library adds](#what-this-library-adds)
2. [What is different](#what-is-different)
3. [What is not available](#what-is-not-available)
4. [Map methods](#map-methods)

The [status table](../README.md#status) gives the current test results.

## What this library adds

| Feature | Description |
|---|---|
| Worker rendering | The renderer can run in a worker. The option is `renderer: 'auto'`, `'worker'` or `'main'`. |
| Server rendering | `renderToSVG` and `renderToImage` draw a map without a browser. See [Server rendering](server-rendering.md). |
| Many markers | A symbol layer draws icons that are always shown from a buffer on the GPU: the cost of a frame does not grow with their number. See [Which icons are fast](markers.md#which-icons-are-fast). |
| SVG images | `addImage` accepts an SVG string. The image is sharp on each screen. Its size in CSS pixels is the size of its `viewBox`, or else of its `width` and `height` attributes, or 24 by 24. |
| Many icons | A symbol layer draws an icon that is always shown (no text, `icon-allow-overlap`) from a buffer on the GPU. Such an icon is not hidden by ground in front of it with 3D terrain, does not fade in, and is drawn below the labels unless its layer is above each layer with labels. See [Markers](markers.md). |
| SVG templates | An SVG string with slots (`{{name}}`) is a template. Each feature gives the slots their values, from its properties or from `params` of the `image` expression: `['image', 'pin', {params: {color: ['get', 'color']}}]`. MapLibre GL JS does not have `params`. See [An image that is a template](api.md#an-image-that-is-a-template). |
| The global state property `color-scheme` | A map of `@map-jr/map-jr-gl` sets the global state property `color-scheme` of the style to `'light'` or `'dark'`, the resolved `colorScheme` of the description. The compat entry does not set it. The name is not reserved in the MapLibre style specification: MapLibre GL JS shows such a style with the default in `state` of the style, so give one (`state: {'color-scheme': {default: 'light'}}`). See [Dark mode](api.md#dark-mode). |
| Fonts | Text uses the glyph files of the style (`glyphs`), as in MapLibre GL JS. A style without `glyphs` needs no glyph files: text then uses the fonts of the browser. The option `glyphs` of earlier versions is removed; to use the fonts of the browser, remove `glyphs` from the style. The style can also give font files in `font-faces`. |
| `queryFeatures`, `querySource` | Find features, with the meaning that they have in `@map-jr/map-jr-gl`. `querySource(sourceId, at, options)` reads the tile data of one source, and you do not need a style layer. `queryFeatures(at, options)` gives what the style layers draw. See [Queries](api.md#queries). |
| `queryElevation` | Gives the elevation at a position from a `raster-dem` source. |
| Contour source | `type: 'contour'` makes contour lines from an elevation source. See [Terrain and elevation](terrain-and-elevation.md). |
| PMTiles | A source URL that starts with `pmtiles://` reads a PMTiles archive. You do not need a plugin. |
| Changes for the server in the style | `metadata["map-jr:ssr"]` on a layer changes that layer only on the server. |
| Images in the style | `metadata["map-jr:images"]` of a style gives images by name. The main entry (`@map-jr/map-jr-gl`) and the server renderer draw them; MapLibre GL JS and the compat entry ignore the key. See [Images in the style](api.md#images-in-the-style). |
| Icons generated on demand | `setMissingStyleImageResolver` supplies an image for a name that the sprite does not contain. |
| `toBlob(type, quality)` | Gives the map as an image: it waits until the map is idle, draws one frame and resolves to a `Blob` of the canvas, with both renderers. Use it instead of `preserveDrawingBuffer`, which has no effect (see "Reading the canvas" in [What is different](#what-is-different)). |
| Frame data | The `stats` event gives the frames per second and the work for each frame. |
| `supported()` | A function of the module. It returns `false` in a browser without WebGL2. MapLibre GL JS has had no such function since version 2. A map that cannot start fires one `error` and shows a message in the container (the class is `map-jr-unavailable`). See [A browser without WebGL2](api.md#a-browser-without-webgl2). |
| Controls without a CSS file | The library adds the styles for its controls to the root node of the container, so a map inside a shadow root has styled controls. You change the colours with `--map-control-*` custom properties. The map option `nonce` sets the nonce of a strict `style-src` on the `<style>` element that a browser without constructed style sheets gets. See [Content Security Policy](loading.md#content-security-policy). |
| The look of the controls | The controls, the popup, the scale and the attribution of the compat entry keep the look of MapLibre GL JS. The round, translucent look, the compass with a dial and the control `colorScheme()` belong to the main API (`@map-jr/map-jr-gl`) only. The popup of both entries fades and grows from its tip when it opens and closes, where the popup of MapLibre GL JS has no animation; `animate: false` turns it off. |

## What is different

| Subject | MapLibre GL JS | This library |
|---|---|---|
| Text | Reads glyph files from the `glyphs` URL. | The same: glyphs and their widths come from the glyph files. Two cases use the fonts of the browser, or the web fonts of `fonts` (the option of the compat entry, or the field of the description of the main API): a character, font stack or range that the files do not have (most ideographs, emoji), and text that the browser must shape (Arabic, Hebrew, Indic scripts). This is like `localIdeographFontFamily` of MapLibre GL JS. A label waits for its glyph file, as in MapLibre GL JS. The map requests the file of the first 256 characters (`0-255`) of each font stack of the symbol layers in view when it starts, at the same time as the first tiles; MapLibre GL JS requests a glyph file only once a tile needs it. |
| Text on lines | Each character follows the line. The style sets the largest angle. | Each character follows the line. A label does not show where the line turns more than about 35 degrees between characters. |
| Order of symbol layers | A symbol layer draws at its position in the layer list. | The labels of all symbol layers draw together, at the position of the last symbol layer that has labels. A layer after that position draws over the labels, as in MapLibre GL JS. A fill, line or other layer between two symbol layers with labels draws below the labels of both. With 3D terrain, the layers on the ground draw below all labels. |
| Label placement | Changes gradually, tile by tile. | The library decides about four times each second. Labels fade between decisions. |
| Feature queries | `queryRenderedFeatures` and `querySourceFeatures` return their result synchronously. | The two methods have the same arguments and return the same features, but the complete result is a promise. Add `await`. The tile data is in a worker. Without `await`, the value of each of the two methods is an array. For `queryRenderedFeatures` the array has the answer of the engine to the same question before (the same view, place and layers). Two rules make that answer present for usual MapLibre code. The map asks the engine about the place of a `mousedown` or `touchstart` and where the pointer rests for 50 ms. A `click`, `dblclick` or `contextmenu` listener that queries `e.point` therefore gets the features at once. When the answer is not there yet, the event waits for it for at most 300 ms, and after that the array has GeoJSON features only. A `mousemove` listener that reads the array gets the same `mousemove` a second time when the answer arrives and the pointer has not moved since, so hover through react-map-gl (`interactiveLayerIds`, `onMouseEnter`, `cursor`) works; the listener sees the first event with an empty array. When an array did not have the complete result, the map fires `idle` again, so code that queries on `idle` gets the features on its next call. Without an answer before, the array has the features of GeoJSON sources only. The features of a GeoJSON source whose data the page has are always read from that data, so they are current after `setData`: this is sufficient for plugins such as mapbox-gl-draw and for code that makes HTML markers from clusters. (For a GeoJSON source with its data at a URL, the first call gives an empty array; the source then fires its data events again, and the next call has the features.) `querySource` is also available: it reads data that the style does not draw. |
| Queries on labels | A label is found on the collision boxes of its text and of its icon. | The same for text at a point and for icons. Text that follows a line is found within 10 pixels of the point of its label, and so is a label whose text is not shown at the moment. |
| Feature state | The GPU applies the state. An `id` can be text. | `setFeatureState` and the `feature-state` expression work. A change builds the tiles of the source again in the background when a layer of that source reads feature state, so it shows after a short time. On a GeoJSON source, the `id` of a feature is its numeric `id`, or the value of the property that `promoteId` names, which can be a number or a string. A GeoJSON feature with a string `id` and no `promoteId` has no `id` for feature state. `promoteId` can also be an object, as in MapLibre GL JS: a GeoJSON source reads the property under the key `_geojsonTileLayer`. On a vector source, the `id` must be the numeric `id` of the feature in the tile. `promoteId` on a vector source has no effect and writes one warning, and a `setFeatureState` call with an `id` that is text (not digits) on a vector source changes nothing and writes one warning for the map. `setFeatureState` and `getFeatureState` with a feature that has no `id` change nothing and write one warning; MapLibre GL JS fires `error`. |
| Style changes | Applied step by step. | A paint value that is the same for all of a layer is applied immediately. Other changes build the tiles of that source again. The old tiles stay on the screen until the new tiles are ready. |
| 3D terrain | Draws terrain at each tilt. | Draws a flat map when you look vertically down. See [Terrain and elevation](terrain-and-elevation.md). |
| Camera | Tilt to 85 degrees. Roll. Field of view. | Tilt to 60 degrees. No roll. A fixed field of view. Padding is available. |
| The lowest zoom | `minZoom` is -2 by default. The world is never less tall than the map. | The same. |
| The `cooperativeGestures` option | The wheel zooms only with Ctrl (⌘ on a Mac), one finger scrolls the page, two fingers move the map, and a hint shows over the map. `map.cooperativeGestures` has `enable()`, `disable()`, `isEnabled()` and `isBypassed()`. | The same behaviour and the same hint. The option `locale` changes the text of the hint, with the keys of MapLibre GL JS (`CooperativeGesturesHandler.WindowsHelpText`, `MacHelpText` and `MobileHelpText`). The event `cooperativegestureprevented` fires with `gestureType` (`'wheel_zoom'` or `'touch_pan'`) and `originalEvent`. `isBypassed()` is not there. The code of the hint loads on demand when the option is on. Until it has loaded, the gestures are blocked and the hint does not show. The hint has its look in its `style` attribute, and the class `maplibregl-cooperative-gesture-screen` for stylesheets. |
| The `hash` option | The camera in the fragment of the URL. | The same, with the same format. |
| Tile URLs | `{z}`, `{x}`, `{y}`, `{bbox-epsg-3857}`, `{quadkey}`, `{ratio}`, `{prefix}`; the `scheme` `tms`. | The same. `{bbox-epsg-3857}` is for WMS servers. `{ratio}` is `@2x` when the pixel ratio of the map is above 1, for every kind of source, as in MapLibre GL JS. |
| The `bounds` of a source | A tile outside the bounds is not requested. | The same, for bounds in the style and in the TileJSON. Not for the bounds in the header of a PMTiles file. |
| An image tile that the server does not have (404) | The nearest tile above it is drawn in its place. | The same, for raster and elevation tiles. |
| GeoJSON sources | `setData`, `getData`, `updateData`, the cluster methods. | The same. `updateData` makes the new data from the old data and the changes, and then replaces the data of the source in one step. |
| `Marker` and `Popup` | Rotation, pitch alignment, offsets, class names. | The same methods. `pitchAlignment` is kept but has no effect: a marker is always upright on the screen. `Popup` has the options `focusAfterOpen`, `closeOnMove`, `trackPointer` and `subpixelPositioning` with the defaults of MapLibre GL JS, and the methods `trackPointer()` and `setSubpixelPositioning()`. A popup that follows the pointer does not move with a touch. With the worker renderer, a marker or popup moves in the same frame as the map during a drag, but it can trail an `easeTo`, `flyTo`, a fling or a pinch by about one frame, because the page learns the camera from the worker after the frame. A symbol layer never trails. See [How closely an element of the page follows the map](markers.md#how-closely-an-element-of-the-page-follows-the-map). |
| `Point` | Re-exports `Point` of `@mapbox/point-geometry`, with about 30 methods. | Exports a smaller `Point` with `convert`, `clone`, `add`, `sub`, `mult`, `div`, `round`, `mag`, `dist` and `equals`. The other methods (for example `rotate`, `unit`, `angle`, `matMult`) do not exist. |
| Private members that wrappers read | `Marker._map`, `Marker._lngLat`, `Map._controls` are internal fields. | `Marker._map`, `Marker._lngLat` and `Map._controls` exist as read-only getters with the same values. Other private members do not exist. |
| TypeScript types | Exports types and classes such as `MapMouseEvent`, `StyleSpecification`, `GeoJSONSource`. | Exports types with the same names (`src/compat-types.ts`). The event and source names are types only: you cannot use them with `new` or `instanceof`. The style types do not check each property: `LayerSpecification` accepts any string as `type` and any names in `paint` and `layout`. `map.on`, `map.once` and `map.off` give the listener the event type that belongs to the name of the event (`MapEventType`, `MapLayerEventType`), and an event name that is not in those lists gets an event of the type `any`. The geometry of a queried feature is the library's own `Geometry` type, which has no `GeometryCollection`. The compat types accept values that are typed with `maplibre-gl`, such as a `StyleSpecification`, a layer, a source or a filter. The reverse direction does not work: a value typed with the compat entry is not always assignable to a type of `maplibre-gl`, and a compat `MapLayerMouseEvent` is not assignable to the one of react-map-gl. A project that uses react-map-gl therefore keeps `maplibre-gl` installed and imports its types from `maplibre-gl`. |
| `isSourceLoaded` | Gives a result for one source. | Gives a result for all sources together. |
| `addImage` | Accepts images and pixel data. | Accepts the same, and also an SVG string or a URL. It returns a promise. |
| `easeTo`, `flyTo` | Accept an `easing` function and an `offset`. | Accept both, as MapLibre GL JS does. `offset` ([x, y] or {x, y}, in CSS pixels) puts `center` at that distance from the centre of the view at the end, also with `bearing` and `pitch`. The library samples the `easing` function at 65 points when the call is made and interpolates linearly between them, so a curve with a change that is narrower than 1/64 of the duration is smoothed. `flyTo` zooms out and back in along the curve of MapLibre GL JS 6.17 (van Wijk and Nuij), with the options `curve`, `speed`, `screenSpeed`, `minZoom` and `maxDuration`; without `duration`, the duration follows from the distance. When the system asks for reduced motion and `essential` is not `true`, `flyTo` jumps, as in MapLibre GL JS. The options `speed`, `curve` and `linear` of `fitBounds` also have no effect and write one warning. |
| Events | Event classes. | Simple objects with `type`, `target`, `point` and `lngLat`. `point` (and each of `points` of touch events) is a `Point`, as is the result of `project()`. |
| Events for one layer | `map.on('click', layerId, fn)` calls the listener synchronously. | The same call works, also with an array of layer ids (`map.on('mouseenter', ['a', 'b'], fn)`). A second argument that is neither a layer id, an array of layer ids nor a function makes `on` throw a `[map-jr-gl]` error. The event fires shortly after the pointer event, because the library reads the tile data. |
| Interaction handlers | `map.dragPan`, `map.scrollZoom`, `map.boxZoom` and others, each with `enable()` and `disable()`. | The same objects are available: `dragPan`, `scrollZoom`, `doubleClickZoom`, `dragRotate`, `touchZoomRotate`, `touchPitch`, `keyboard`, `boxZoom`. `isActive()` always returns `false`. Box zoom works as in MapLibre GL JS: a drag with Shift held and the left mouse button draws a box, zooms to it, and fires `boxzoomstart`, `boxzoomend` (with `boxZoomBounds`) or `boxzoomcancel`. Box zoom does not work with touch input. With `interactive: false`, every handler is off, and the map still fires `click`, `mousemove` and the events of layers, as in MapLibre. The `interactive` option of `@map-jr/map-jr-gl` behaves the same. |
| Rotate drag (the right mouse button, or Ctrl with the left one) | More than 100 pixels above or below the centre of the map, the map turns by the angle that the pointer makes around that centre. Nearer to the centre, the map turns by 0.8 degrees for each pixel sideways: a drag to the right increases the bearing below the centre and decreases it above the centre. The map pitches by 0.5 degrees for each pixel up. After the drag, the map turns on with inertia. A drag with Ctrl and the right button rolls the map. The compass of `NavigationControl` turns the map by the angle around the centre of the button. | In `@map-jr/map-jr-gl/maplibre-compat`, the drag turns and pitches the map by the same angles (measured against MapLibre GL JS 6.17.0 at five heights of the map). The map stops when the drag ends, without inertia. A drag with Ctrl and the right button turns and pitches the map, because there is no roll. The options `rotateSpeed`, `pitchSpeed` and `aroundCenter`, and an object as `dragRotate` (`around`, `movement`), have no effect. The compass turns the map by 0.4 degrees for each pixel sideways: a drag to the right decreases the bearing. In `@map-jr/map-jr-gl`, the drag on the map does the same as the compass at every height of the map, which is the opposite direction to MapLibre GL JS below the centre of the map, at half the rate. |
| Pointer events | `mousedown`, `mouseup`, `touchstart` and others, with `preventDefault()`. | The same events. A listener that calls `preventDefault()` on `mousedown`, `touchstart`, `wheel` or `dblclick` stops the map from acting on that gesture. |
| `setWorkerUrl` | Sets the URL of the worker file of MapLibre GL JS. | Sets `workerUrl` of `configure`. The URL must point to `map-jr-gl-worker.js`. A URL whose file name contains `maplibre-gl` and `worker` (such as `maplibre-gl-worker.mjs`) is ignored with one warning, and `getWorkerUrl()` then still returns `''`. Remove the call: the library finds its worker file itself. |
| Requests | The `transformRequest` option and `addProtocol`. | The same. The functions run on the page; the workers ask the page for each request that they apply to. A protocol named `pmtiles` is not used: the library reads `pmtiles://` URLs itself, and `addProtocol('pmtiles', …)` warns once in every build. Remove that call. |
| `Marker`, `Popup` | Full API. | The usual parts of the API: position, popup, drag, anchor, offset. `offset` and `setOffset` take `[x, y]`, `{x, y}` or a `Point`. `getOffset()` returns a `Point`, as in MapLibre GL JS. |
| `addImage` with an image that draws with WebGL | Accepts an image whose `data` has `renderWithWebGL` (`StyleImageWebGLData`). | Not supported. The promise rejects with an error that names the image, and the map keeps working. |
| `getImage` | Returns the decoded RGBA pixels. | Returns `{width, height, data: Uint8Array}` RGBA pixels for an image added as pixels, a canvas, an image element or a bitmap. For an image added as a URL or as SVG text, `data` is the string that `addImage` was given, because decoding it again is asynchronous. |
| Touch gestures | You can configure each gesture. | The same gestures. They are always on. |
| Expressions | Checks the types. | Does not check the types. An expression that is not correct can give no error. |
| Style validation | Reports errors in the style. | Does not validate the style. It writes a warning for each layer or property that it cannot draw. Four calls fire `error` and change nothing, as in MapLibre GL JS: `addLayer` with an id that exists, `addLayer` with a source that the style does not have, `addSource` with an id that exists, and `removeSource` of a source that a layer uses. |
| Reading the canvas | `canvasContextAttributes: {preserveDrawingBuffer: true}` keeps the image, so `getCanvas().toDataURL()` works at any time. | `preserveDrawingBuffer` has no effect, and `new Map()` warns once and names `map.toBlob()` (see the next row). With the worker renderer, `getCanvas().toDataURL()`, `toBlob()` and `drawImage(map.getCanvas())` give the last frame at any time. With the main renderer, the browser may clear the drawing buffer after each frame (WebGL allows this, and the reviews of 2026-11-12 saw a blank image), so they give the frame reliably only inside a `render` listener (call `triggerRepaint()` to get one). Use `map.toBlob()`, which works with both renderers and waits for the tiles. Read the canvas after `idle`, not after `loaded()` returns true. |
| Options and layers with no effect | | The constructor options `projection` (which MapLibre GL JS 6.17 does not have either: use the style or `setProjection`), `renderWorldCopies: false`, `canvasContextAttributes` (other than `antialias`), `logoPosition` and `validate` have no effect. Each writes one warning. The globe: the root property `projection` of a style, `setProjection` and `GlobeControl` take `globe`, `vertical-perspective` and expressions of them, and `getProjection` returns the projection of the style as it was given, or `undefined` when the style has none, as in MapLibre GL JS. `projectiontransition` fires with `newProjection` for each new style and when the name of the projection changes. On the globe, 3D terrain, `fill-extrusion` layers, custom layers and the atmosphere of `sky` are not drawn yet (one warning per map; they show past zoom 12), `maxBounds` has no effect (as in MapLibre GL JS), a drag turns the globe as MapLibre GL JS 6.17 does (the centre after a drag agreed within 0.3° in 36 measured drags), and `queryRenderedFeatures` is less exact near the horizon. On the globe, `jumpTo`, `easeTo`, `flyTo`, `panBy` and `setCenter` without a `zoom` keep the size of the globe and change the zoom, as in MapLibre GL JS, and `flyTo` follows MapLibre's curve on the globe (the lowest zoom of three measured flights agreed within 0.01). A drag toward a pole at `minZoom` stops at `minZoom`, where MapLibre GL JS goes slightly below it (-2.035 against -2 in one measured drag). A switch from Mercator to the globe shows the globe when the tiles of the view are built again with the cut for the globe (or after 1 s at most), so the edge of the globe does not show the background in wedges; MapLibre GL JS switches at once and shows such wedges for a moment. A label whose anchor turns behind the globe is not drawn from that frame on; MapLibre GL JS 6.17 hides it only at its next placement and fades it out, so that during a fast drag its labels show through the globe for a moment (for at least 160 ms in one measured drag at 1500 px/s). The server renderer draws Mercator. Another name (for example `identity`) writes a different warning, and the map draws Mercator. `NavigationControl` follows `visualizePitch` as MapLibre GL JS does: by default (false) dragging the compass only rotates the map, a click resets only the bearing, and the compass does not show the pitch; with `visualizePitch: true` the compass shows the pitch, dragging it also pitches the map, and a click resets both. A drag of more than 3 pixels that ends on the compass does not reset the bearing. A drag that starts on the compass turns the map as a drag on the map with the right mouse button does: 0.4 degrees of bearing for each pixel sideways, wherever the pointer is. MapLibre GL JS turns the map by the angle of the pointer around the centre of the compass, which changes little once the pointer is far from it. The option `container` of `FullscreenControl` has no effect and writes one warning: the control puts the container of the map into fullscreen. The map option `fadeDuration` (other than 300) has no effect and writes one warning, because labels fade for a fixed time. The map option `pitchWithRotate: false` has no effect and writes one warning, because a drag with the right mouse button always turns and tilts the map. The option `locationOccludedOpacity` of `Popup` has no effect, and writes one warning per page when it is given. A `Marker` on the far side of the globe takes `opacityWhenCovered` (default 0.2) and the class `maplibregl-marker-covered`, as in MapLibre GL JS; 3D terrain does not cover a marker. `setStyle` always replaces the whole style, as MapLibre GL JS does with `diff: false`. The option `diff: true` (the default of MapLibre GL JS) gives the same style, but without the shorter update, and it writes no warning, because wrappers such as react-map-gl pass it on every style change. |
| `setTransformCameraUpdate` | Calls the function before each frame and draws the camera that it returns. react-map-gl 8 gives every map such a function, so that a controlled map (`viewState` with `onMove`) never draws a camera that differs from `viewState`. | Calls the function after each `move` event and does not apply what it returns. A controlled react-map-gl map works when `onMove` sets `viewState` to `e.viewState`, and a change of `viewState` from outside moves the map. When `onMove` changes the camera (for example when it limits the latitude), the map draws the camera of the gesture, and goes to the camera of `viewState` when the movement ends. The map writes one warning the first time the function changes the camera, and no warning for a map where it does not. To keep the map in a region, use the option `maxBounds`. |
| A listener that throws | The error leaves `fire`, and the listeners after it do not get the event. | Each listener gets the event, and what a listener threw is an `error` event. |
| A query and `remove()` | The result is synchronous. | The promise of a query that has no answer yet, or that is asked after `remove()`, rejects with the error `[map-jr-gl] The query has no answer: the map was removed.` After a lost WebGL context it rejects in the same way, and the message says to ask again. |
| `strict` | | The constructor option `strict: true` makes each of these warnings and `error` events an error that is thrown. Use it in tests and while you change from MapLibre GL JS. The default is `false`. |
| CSS class names | `maplibregl-*` | `map-jr-*`. Each element also has the `maplibregl-*` name, so stylesheets and plugins for MapLibre GL JS continue to work. In `@map-jr/map-jr-gl/maplibre-compat`, the container has `maplibregl-map`, the canvas has `maplibregl-canvas`, and the buttons of the controls have `maplibregl-ctrl-zoom-in`, `maplibregl-ctrl-zoom-out`, `maplibregl-ctrl-compass`, `maplibregl-ctrl-fullscreen`, `maplibregl-ctrl-geolocate` and `maplibregl-ctrl-terrain`. There is no `maplibregl-canvas-container` element: `getCanvasContainer()` returns the container. As in MapLibre GL JS, that element has `maplibregl-touch-drag-pan` while `dragPan` is enabled and `maplibregl-touch-zoom-rotate` while `touchZoomRotate` is enabled. There is no `maplibregl-control-container` element either: the four corners of the controls (`maplibregl-ctrl-top-left` and the others) are children of the container, so a selector that contains `.maplibregl-control-container` matches nothing. A popup has no `maplibregl-popup-anchor-*` class, and its tip is a rotated square inside the box of the popup, so CSS that targets the anchor classes or styles the tip as a border triangle has no effect. The state names of the buttons (such as `maplibregl-ctrl-shrink`) and `maplibregl-ctrl-icon` are not set. A control from a plugin gets the `map-jr-*` names when you add it. As in MapLibre GL JS, the container sets the font (`12px/1.3 system-ui, sans-serif`, where MapLibre uses Helvetica Neue) and the controls inherit it, and the canvas of an interactive map has `maplibregl-interactive` and shows the `grab` cursor, or `grabbing` while a button is down. |
| `setStyle` in the constructor | The constructor calls `this.setStyle(options.style)`, so a subclass or a patch of `Map.prototype.setStyle` sees the first style. | The constructor loads the first style without a call of `setStyle`. A patched `setStyle` runs only for later calls. To change the first style, change `options.style` before you construct the map. |
| Images added at run time | | All images that `addImage` adds share one texture of 2048 by 2048 pixels (in device pixels, so an image takes four times its area on a screen with a pixel ratio of 2). When a new image finds no free place, the map packs all of its images again; when they still do not fit, it reports one error, and later images are not drawn. Remove images that the map no longer needs. See `docs/api.md`. |

A GeoJSON source has `setData`, `getData`, `updateData`, `getClusterExpansionZoom`, `getClusterChildren` and `getClusterLeaves`, which give promises. An image source has `updateImage` and `setCoordinates`. A vector, raster or raster-dem source has `setTiles` and `setUrl` (see [Source methods](#source-methods)). The object is a new copy at each call. |

Without a position, `addControl(undefined)` throws a `TypeError`. | In `@map-jr/map-jr-gl/maplibre-compat`, fires `error` and returns the map, with or without a position. A position that does not exist throws an error that names it, before `onAdd` runs; MapLibre GL JS calls `onAdd` and then throws a `TypeError`. |

A missing key keeps the English text. | The same keys as MapLibre GL JS 6.17.0, for the buttons of the controls, the units of `ScaleControl` and the hint of `cooperativeGestures`. A missing key keeps the English text of this library, which differs from MapLibre's in places (the compass is "Reset bearing to north"). `map._getUIString(key)` returns the text of the option, or `undefined` for a key that the option does not have. The close button of `Popup` (`Popup.Close`) and the name of the default `Marker` (`Marker.Title`) take the text when they are added to the map; a `Marker` with an element of your own keeps its attributes. A value that is not an object writes a warning and is ignored. The main API (`@map-jr/map-jr-gl`) has no `locale` yet: its controls have English names. |
| `FullscreenControl` | Uses the Fullscreen API, and falls back to "pseudo fullscreen" (the class `maplibregl-pseudo-fullscreen`, which makes the container fill the window) where the browser has none, or with `pseudo: true`. | The same, with the option `pseudo` and the same class (the container has `map-jr-pseudo-fullscreen` too). `fullscreenstart` and `fullscreenend` fire in both modes. | Custom layers | `addLayer` takes a custom layer (`CustomLayerInterface`, `type: 'custom'`) on every map. | `addLayer` takes a custom layer on a map that was made with `renderer: 'main'` (or after `configure({renderer: 'main'})`), because only the renderer on the main thread shares its WebGL context with the page. With another renderer, `addLayer` fires `error` with a message that says to pass `renderer: 'main'`, and adds nothing. `onAdd(map, gl)` runs once. `onRemove(map, gl)` runs on `removeLayer` and on `remove()`. As in MapLibre GL JS 6.17, `setStyle` keeps the custom layers with `diff` (the default), each before the layer that came after it, and drops them with `diff: false`; neither calls `onRemove`. `render(gl, args)` gets the same fields as in MapLibre GL JS 6 for the Mercator projection: `defaultProjectionData.mainMatrix` (for the x, y and z of a `MercatorCoordinate`), `modelViewProjectionMatrix`, `projectionMatrix`, `nearZ`, `farZ`, `fov`, `shaderData` and `getProjectionData`. The matrices are `Float64Array`s. They put a point on the same pixel as in MapLibre GL JS, but some values are close and not equal: the near and the far plane are those of this library (at pitch 0 on a map 300 pixels high, `nearZ` and `farZ` are 45 and 1800, where MapLibre GL JS gives 6 and 454.5), so the depth rows of `projectionMatrix` and of the other matrices differ; a height in `mainMatrix` is 0.11 % lower, because the map turns metres into pixels with the radius of Web Mercator (6,378,137 m) and `MercatorCoordinate` uses 6,371,008.8 m; and the depth range of a `'3d'` layer is 0 to 1, where MapLibre GL JS uses 0 to 0.99915. `prerender(gl, args)` runs directly before `render` of the same layer, and not before the whole frame. A layer with `renderingMode: '3d'` draws with the depth test and shares the depth buffer with 3D terrain and with the fill-extrusion layers below it; a fill-extrusion layer above it does not see its depth. A custom layer follows the rule of "Order of symbol layers" above, and with 3D terrain it draws in 3D, below all labels. After the code of the layer, the map restores the GL state that it needs. After a lost WebGL context, the map restores it and the custom layers keep their places: `onAdd` runs again with the new context, and `render` gets that context. (MapLibre GL JS does not call `onAdd` again.) `getStyle()` leaves custom layers out, and `getLayer(id).implementation` is the object of the layer, as in MapLibre GL JS. `renderToTerrainTile` and `renderTerrainHeightMap` are not available. The code of custom layers (about 2 KB gzip) loads with the first custom layer. `MercatorCoordinate` is exported with `fromLngLat`, `toLngLat`, `toAltitude` and `meterInMercatorCoordinateUnits`, and gives the values of MapLibre GL JS. |
| `map.painter` and `GPUInitializationError` | The map has a `painter`. When WebGL cannot start, the constructor throws a `GPUInitializationError`. | The map has no `painter`, so a check such as `if (!map.painter) throw new GPUInitializationError(...)` throws for every map. Call `supported()` before you create the map instead. In the development build (the `development` export condition, `dist/*.dev.js`), reading `map.painter` warns once per map and says what to write instead; the value is `undefined` in both builds. `@map-jr/map-jr-gl/maplibre-compat` exports `GPUInitializationError` (also on the default export). When the map cannot start, the constructor does not throw: the map fires `error` with a `GPUInitializationError` and shows a message in the container. |

## What is not available

Sources:

- Video and canvas sources
- MapLibre Tiles (MLT)
- `promoteId` in vector sources

Layers:

- Color relief
- Custom layers with the worker renderer (see "Custom layers" in [What is different](#what-is-different))
- `fill-extrusion-pattern`
- Patterns that are different for each feature

Properties:

- `line-gradient` together with `line-dasharray`
- `line-offset` and `line-blur` that are different for each feature
- `circle-pitch-alignment` and `circle-pitch-scale`
- Circle stroke and blur that are different for each feature
- `icon-halo-blur`. Icon halos are available for distance-field (SDF) icons.
- `text-writing-mode`
- `text-pitch-alignment` with a value other than `auto`. On a tilted map, text along a line lies on the ground and other text is upright, which is what `auto` gives in MapLibre GL JS.
- `symbol-z-order` and `symbol-avoid-edges`
- An icon together with text that follows a curved line. The text is drawn without the icon.
- `vertical-align` in `format` text. Sizes, fonts, colours and images in `format` text are available. The SVG output of the server draws each line in one size.

Layers that the server renderer does not draw:

- Heatmap and relief shading

Other:

- Sky and fog, the atmosphere around the globe, and projections other than `mercator`, `globe` and `vertical-perspective` (`addProjection`)
- The layer type `color-relief`
- The right-to-left text plugin. The browser draws right-to-left text correctly without it.
